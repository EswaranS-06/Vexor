How Vexor works

One host, one CLI, five security tools wired into each other. This guide follows the README section by section, with the moving parts drawn out. Every visual below is interactive.

What you get

Vexor runs each tool from its official image and does the wiring between them: certificates, users with the least access they need, alert forwarding, retention and health checks. Pick a component to see its role and its commands.

Requirements

Linux with systemd, Docker Engine 24+ with Compose v2, and python3 openssl curl ss flock. RAM and ports depend on what you run; pick it below.

    Quick start

    Three commands bring up Wazuh; one or two more add each tool. The first start takes one to two minutes.

    1. Clone and install

      Creates .env, generates passwords, the cluster key and every certificate, removes the demo users, starts the stack.

      git clone https://github.com/EswaranS-06/Vexor.git
cd Vexor && sudo ./vexor install

    2. Turn on self-healing

      vexor on PATH, start at boot, watchdog, hourly health check, backups.

      sudo ./vexor daemon install
vexor info --show-secrets

    3. Add the rest of the SOC

      Open n8n right after enabling it: its first visitor becomes the owner.

      vexor suricata enable && vexor zeek enable
vexor soc both
vexor n8n enable && vexor n8n connect && vexor n8n workflow
vexor n8n test

    4. Enroll an endpoint, trust the certificate

      Copy-paste install commands for Windows, Linux or macOS, and a local CA so browsers stop warning.

      vexor agents enroll-cmd windows --name pc-01
vexor cert create && vexor cert export-ca

        Change management

        Edited something? Pick it to see how to apply it and what restarts.

        Never apply settings with down -v or reset. They delete the volumes that hold every alert, agent key, rule and workflow.

        vexor restart recreates manager containers: the Wazuh image applies the mounted ossec.conf only to a fresh container. The data lives in volumes, so this is safe. In .env, never put a comment after an empty value: Compose reads KEY= # note as the value # note.

        Data, retention and backups

        How long each kind of data is kept by default. Bars are to scale; change the days in .env.

        What vexor backup saves, daily at BACKUP_TIME

        • Wazuh indexer snapshot
        • Master state: agent keys, rules, groups, API users
        • n8n, Grafana and Portainer volumes
        • .env, config/ and certificates
        • Elasticsearch data: not yet (vexor volumes backup elk-es-data --stop)

        Keep .env: it holds N8N_ENCRYPTION_KEY, without which n8n credentials cannot be decrypted.

        Self-healing

        vexor daemon install sets up a boot service and four timers. Play a day to see when each one runs and what it does.

        00:0006:0012:0018:0024:00

        • health · hourly

          Security

          Who should reach which port. Everything else stays on the host or the internal Docker network.

          • Every UI only through nginx, TLS 1.2/1.3; indexer and Elasticsearch bound to 127.0.0.1.
          • Least-privilege users: Grafana reads Wazuh indices; Logstash writes vexor-*; vexor-n8n runs agent actions; vexor_n8n reads vexor-*.
          • Alerts to n8n carry a secret X-Vexor-Token; the starter workflow drops calls without it.
          • Demo indexer users with public passwords are removed at install; doctor fails if they come back.
          • Enrollment is open by default: vexor agents password on.
